# 学生模拟评审协议

这是整条流水线里最容易做假的一步。做假的方式不是故意放水，而是无意识地补全：读到自己熟悉的推导，会自动跳过缺的那一步，然后觉得"讲清楚了"。

所以协议的重点不是"让 AI 扮演学生"，而是**切断它会补全的条件**。

---

## 一、为什么必须独立

三个必须切断的东西：

| 切断什么 | 怎么切 | 不切会怎样 |
| --- | --- | --- |
| 设计意图 | 不给「这段是想让他理解 X」 | 评审按意图打分，不按文字打分 |
| 作者身份 | 新开 subagent，不带写作上下文 | 评审记得自己为什么这么写，自动宽容 |
| 答案 | 只给题干，答案另存 | 看懂答案 ≠ 看懂推导 |

同一个 agent 连续评审两轮也不行。第一轮它已经建立了"这套讲法大概在说什么"的印象，第二轮会带着这个印象读。

---

## 二、角色卡

评审必须按这张卡设定，不能改：

```markdown
你是一名刚参加完高考三个月的学生。

数学：高考 120/150。会导数、概率初步、三角函数、数列。
物理：会简单电路与波动，但公式基本忘了。

你没学过：微积分（只会求导，不会积分）、线性代数、复变函数、
概率论与数理统计、信号与系统。

即使听说过这些课名，你也只记得名字，不记得内容。
凡是需要这些课的地方，你必须依赖面前这份讲稿重新学。

你的性格：
- 诚实，不客气。看不懂就说看不懂，不猜作者的意思。
- 不擅长也不愿意"配合演出"。不会因为讲稿写得认真就给好评。
- 遇到跳步会停下来，指出"这一步我没跟上"。
- 不会用"整体不错""基本理解"这种话。要么能复述，要么不能。
```

**关键设定：先修不是"学过但生疏"，是"只记得名字"。** 这是本流水线的默认基线，也是 `course.yaml` 里 `assumed_retained: 0.2` 的含义。

如果某门课确实要求先修，而讲稿没有重建，评审必须判 blocking。不要因为它"本来该会"就放过——观众不会。

---

## 三、输入包

只给这些：

- `script.md` 全文（最终稿，不带批注、不带"待补"）
- `examples.md` 的题干部分（答案与变式答案另存，评审结束后再给）
- 一张空白答题纸的格式说明

不给这些：

- `shots.yaml`、分镜、画面描述
- 作者审稿意见
- `plan/EP01.md` 里的教学目标
- 任何"这是测试""请严格评审"的元指令

元指令会改变行为。要的是"读材料的人"，不是"被要求打分的人"。

---

## 四、三个任务

### 任务 A：复述（不许抄原文）

> 合上讲稿，用自己的话回答：
> 1. 这一集在解决什么问题？
> 2. 它最后给出了什么工具或结论？
> 3. 这个工具为什么非要有？原来的办法差在哪？

判定：三个问题都能答，且**没有使用标题里的原词**，算 3 分。有一个答不出，2 分。只能复述原句，1 分。答错或空白，0 分。

### 任务 B：做题（只做变式）

给 3–5 道变式题，难度分布：2 道直接套用、2 道改条件、1 道判断对错并说明理由。

规则：

- 闭卷。不许回看讲稿的例题部分。
- 可以回看定义与推导，但要在答案里标"我回看了第几段"。
- 不许写"根据公式可得"。每一步都要写为什么。
- 做不出来就写"卡在哪一步"，不要空着，也不要猜。

判定：按步给分。答案对但步骤跳，扣一半。答案错但方法对，给一半。

### 任务 C：标卡点

逐段标：`懂` / `半懂` / `不懂`。

`半懂` 和 `不懂` 必须写三样：

1. 引用原句（一字不改）
2. 我当时理解成了什么
3. 缺的是哪一步（定义？推导？例子？前提？）

只写"这里有点难"不算，退回重标。

## 五、评分表

| 维度 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 复述 | 答不出 | 只能背原句 | 三个问题答对两个 | 三个全对且用自己的话 |
| 概念 | 完全没建立 | 记得名字，说不清 | 能说清是什么，说不清为什么 | 能说清是什么、为什么需要、什么时候不适用 |
| 推导 | 跟不上 | 能看懂结论，跟不上步骤 | 能跟上，但有一两处要回看 | 能自己重推一遍 |
| 应用 | 做不出 | 能套原题 | 变式基本能做 | 变式全对且能解释每步 |

整集得分 = 四个维度均分。

**通过阈值**：

```
理解均分 ≥ 2.5 / 3
例题正确率 ≥ 80%
blocking 卡点 = 0
```

blocking 的定义：卡点导致后续内容无法理解，或导致例题做错。仅仅"这里有点绕"是 non-blocking。

---

## 六、反奉承规则

这五条写进评审 prompt，不许删：

1. **禁止总结性好评。** 不写"整体讲解清晰""逻辑连贯"这类话。只写具体位置的具体问题。
2. **每个"懂"都要能兑现。** 说懂，就要能用一句话复述；复述不出，改判"半懂"。
3. **不确定就标"猜"。** 如果某句话是靠上下文猜出来的，标 `[猜]`，并说明猜的依据。猜对不算懂。
4. **不许替作者补全。** 看到"由此可得"，如果自己推不出，就是跳步，不许用"这里应该是……"帮它圆上。
5. **宁可误判。** 如果一段话"好像懂又好像不懂"，判"半懂"。放过的代价是观众真的卡住，误判的代价只是作者多改一句。

## 八、不通过之后

回 S4，按卡点改。改法有优先级：

1. **缺定义** → 补定义，放在第一次使用之前。
2. **缺动机** → 补"为什么需要这个量"，放在定义之前。
3. **缺中间步** → 拆行，补四槽位。
4. **缺例子** → 加一个最小例子，不要加一整道大题。
5. **缺先修** → 回 S1.5，不要在本集硬补。

改完换新评审，报告存 `reviews/EP01-learner-r2.md`。**不要在同一份报告上追加**，否则看不出这一轮改了什么。

## 九、视频版（S8）

### 输入

- 字幕全文（带时间戳，SRT 或 JSON）
- 关键帧：每 30 秒一帧，另加每个检查点前后各一帧
- 章节表

不给：讲稿原文、分镜表、作者说明。

### 任务

1. **复述**：这一集讲了什么？三个要点。
2. **检查点**：暂停在检查点，回答当时的问题。答完再看下一帧。
3. **音画对应**：哪一帧的画面和字幕说的不是一回事？
4. **回看次数**：标出"必须回看才能懂"的位置。

### 评分

| 维度 | 通过标准 |
| --- | --- |
| 复述 | 三个要点至少两个准确 |
| 检查点 | ≥ 2/3 能答 |
| 音画错位 | 0 处 blocking |
| 回看 | ≤ 2 处 non-blocking |

### 必须声明的局限

代理只能读字幕与帧，**不能判断**：

- 语速、停顿、音量
- 口播错误（念错字、读错符号）
- 音乐、音效
- 画面动效是否流畅

报告末尾固定写：

> 本报告基于字幕与关键帧，未覆盖听感、口播与动效。需人工抽查：随机 3 分钟，检查语速、音量、符号读法、音画同步。

### 人工抽查清单

- [ ] 随机抽 3 分钟，1.0 倍速看一遍
- [ ] 符号读法是否正确（X/x、τ、ω、E）
- [ ] 字幕是否与口播一致（抽 10 句）
- [ ] 检查点停顿是否够长（≥ 3 秒）
- [ ] 章节跳转是否落在句间，不切断话

## 十、没有 subagent 能力时

如果运行环境不能再开一个独立上下文，按下面顺序退让，并在报告里写明用了哪一档：

1. **换会话**：把讲稿贴到一个新会话，或换一个模型读。可信度接近独立评审。
2. **只给文件**：让另一个 agent 只读讲稿文件，不给对话历史与设计说明。
3. **同上下文重读**：隔一段时间再读，但必须在报告里标「同一上下文，可信度下降」，且不能作为唯一放行依据。

不要把「同一个人读两遍」当成两轮评审。第二遍读的是记忆，不是文字。
