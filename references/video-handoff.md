# 视频交接

S7 把讲稿交给 `code-course-video`。本文件定义接口：我们的 `shots.yaml` 怎么变成它能吃的三个 JSON，以及数学/信号类课程必须改的那一处。

---

## 一、它要什么

`code-course-video` 的核心是三个文件：

| 文件 | 作用 | 谁生成 |
| --- | --- | --- |
| `course.json` | 场景、画面内容、字幕、章节、帧数 | 我们映射 |
| `anchors.json` | 每句旁白对应哪几行/哪个对象 | 人工确定语义后写入 |
| `words.json` | 最终音频的词级时间 | 配音后由对齐工具生成 |

它的约定是**语义与计时分开**：先人工确定"这句话讲哪一行"，再用最终音频定位时间。不要反过来按字数均分。

---

## 二、字段映射

### shots.yaml → course.json

| shots.yaml | course.json | 说明 |
| --- | --- | --- |
| `id` | `scenes[].key` | 全局唯一 |
| `duration` | `scenes[].durationFrames` | 秒 × fps，向上取整 |
| `visual: formula` | `scenes[].code` | 公式按行存，一行一个等号 |
| `highlight` | `scenes[].initialCodeLines` | 进场即选中，不要等动画 |
| `caption` | `scenes[].captions[]` | 按实际说完时间结束 |
| `unit` | 章节归并依据 | 同一 unit 可跨多个 scene |
| `pause_after` | 场景尾部静音 + 帧数 | 不要用空白画面凑 |

`shots.yaml` 里的一个 shot 通常对应 `course.json` 的一个 scene。公式太长要跨页时，拆 scene，不要压缩字号。

### shots.yaml → anchors.json

```json
{
  "scenes": {
    "EP01-S012": {
      "audioMeta": "EP01.words.json",
      "initialCodeLines": [1],
      "cues": [
        {"phrase": "自相关函数等于", "lines": [1]},
        {"phrase": "取数学期望", "lines": [1, 2]}
      ]
    }
  }
}
```

规则：

- `phrase` 是旁白里的**原话片段**，不是概括。要能被 `timeline_tools.py resolve` 唯一匹配；匹配到多处就写清第几次出现。
- `lines` 是公式行号，从 1 开始，按 `\n` 切分。
- 一句话讲两行，就写 `[1, 2]`；下一句开始时才移动高亮。
- 句末、静音、思考期不清除高亮。

### words.json

由配音后的对齐工具生成，不要手写。`timeBase` 必须是 `final-audio`——所有时间以最终音频为准，不以文稿字数估算。

## 三、数学/信号课必须换帧

`code-course-video` 自带的 `CourseFrame.tsx` 是代码课骨架：左代码、左下输出、右注解。

数学、信号、物理课要换成：

```
┌─────────────────────────────┬──────────────┐
│  公式区（KaTeX / MathML）    │  注解区      │
│  一行一个等号                │  这一步在   │
│  当前行持续高亮              │  干什么     │
├─────────────────────────────┤              │
│  图区（波形 / 谱 / 相图）    │              │
│  对象 + 状态分别控制         │              │
├─────────────────────────────┴──────────────┤
│  字幕（独立层，关闭时不重排）               │
└────────────────────────────────────────────┘
```

**关键：公式行就是"代码行"。**

把每个公式行当成一行代码，`lines` 索引照用。这样高亮机制、分幕隔离、锚点解析全都不用改，只换渲染组件。不要为了"这是数学课"重写同步逻辑——那是最容易引入错行的地方。

图区按原技能的"图示对象与状态"处理：

- 对象：坐标轴、曲线、标注、箭头，各有稳定 ID。
- 状态：曲线位置、阴影范围、箭头方向，由旁白触发。
- 对象缺失时补一个小幕，不要只换索引。

## 四、同步流程

顺序不能变：

1. **定稿讲稿**（S6 已通过）
2. **定稿分镜**：每句话讲哪个对象，人工写进 `anchors.json`
3. **配音**：按最终稿生成，处理变速与停顿
4. **对齐**：用最终 PCM 生成 `words.json`
5. **校验**：`timeline_tools.py validate` + `resolve`
6. **试片**：60–90 秒，覆盖长公式、图状态、高亮切换、字幕换行
7. **分章渲染**

第 2 步在第 3 步之前。先配音再想"这句话讲哪一行"，必然对不上。

---

## 五、验收分层

原技能的三层验收，照搬：

| 层 | 结论 | 不能替代 |
| --- | --- | --- |
| 有选中行 | 高亮存在 | 不代表选对了 |
| 语义对应 | 这句话确实讲这一行 | 不代表成片对 |
| 实际 MP4 正确 | 抽帧核对过 | 不代表全部看完 |

报告里必须分开写。不要用"高亮覆盖率 100%"代替"语义对应"。

加上本流水线特有的两项：

- **先修覆盖**：每个标记为先修的知识点，是否在画面上有对应的重建片段。
- **检查点停顿**：每个检查点是否有 ≥ 3 秒的实际静音（用音频测，不用稿子估）。

## 六、交付清单

```markdown
- [ ] video/EP01.mp4
- [ ] video/EP01.course.json
- [ ] video/EP01.anchors.json
- [ ] video/EP01.words.json
- [ ] 字幕（内嵌或外挂，与母版同版本）
- [ ] 章节表 chapters.txt（首行 00:00:00）
- [ ] 抽帧报告（12 个时间点）
- [ ] 验收记录（三层 + 先修覆盖 + 停顿）
- [ ] 未测项清单
```

验收记录要绑定本次视频与时间轴的哈希。改了任何一帧，旧记录作废。

## 七、常见错

| 错 | 后果 | 正确做法 |
| --- | --- | --- |
| 按字数均分时间 | 长句被压、短句拖沓 | 用最终音频的实测时间 |
| 一句话里高亮两处不相关对象 | 观众不知道看哪 | 拆句，或只选一处 |
| 公式换行后行号没重算 | 高亮错行 | 每个 scene 重新定初始行 |
| 用动画结束时间控制高亮 | 说到一半就消失 | 高亮持续到下一处讲解开始 |
| 字幕按字数断句 | 断在词中间 | 按语义断，按实际说完时间结束 |
| 先渲染再改稿 | 全部重来 | S6 通过才进 S7 |
