# 技能检索与整合

S2 的目标不是"多装几个技能"，而是给每个知识点找到两样东西：**谁来教**、**谁来画**。

找不到就写"自建"，不要硬套一个不匹配的技能。

---

## 一、检索顺序

从近到远，前一层有结果就不要跳过：

| 层 | 查什么 | 怎么查 |
| --- | --- | --- |
| 1 | 本地已装技能 | 读 `~/.config/opencode/skills/` 下的 `SKILL.md` 描述 |
| 2 | 已知仓库 | 之前用过、确认可用的（如 `code-course-video`、`dialogue-tutor`） |
| 3 | GitHub / Web | 关键词组合，见下 |
| 4 | 学科开源教材 / 代码 | 用来核对内容与生成素材，不当教学法用 |

关键词至少换三种说法，中文一次、英文一次、领域词一次：

```
随机信号分析 + skill / 教学 / 讲稿
random signal analysis + course / tutorial / visualization
autocorrelation + PSD + interactive / notebook
```

只搜一种说法，漏掉率很高。

---

## 二、三类技能，不能互相替代

| 类型 | 提供什么 | 典型例子 | 用错会怎样 |
| --- | --- | --- | --- |
| 内容型 | 学科知识、公式、章节体系 | signal-processing 知识库 | 当成讲法用，写出来还是百科条目 |
| 教学法型 | 怎么讲、按什么顺序讲、哪里停 | dialogue-tutor 的行行推导 | 当成内容用，知识本身可能是错的 |
| 生产型 | 渲染、配音、对齐、字幕 | code-course-video | 当成讲法用，画面很漂亮但没讲明白 |

一个知识点通常要配 1 个教学法 + 1 个素材源 + 1 条生产链。三者都空，就是自建。

---

## 三、评估维度

每个候选按这六项打分（1–5），写进 `skills.lock.md`：

| 维度 | 问什么 |
| --- | --- |
| 学科匹配 | 它讲的是不是这门课的内容？同名不同课的要当心 |
| 输出类型 | 它产出知识、讲法、素材，还是成片？ |
| 可集成 | 输出能不能被下一步直接吃？要手改多少？ |
| 可复现 | 有没有固定种子、版本号、参数记录？ |
| 许可 | 能不能商用、能不能改、要不要署名？ |
| 维护 | 最近一次更新是什么时候？issue 有没有人管？ |

**可复现是一票否决项**。视频课要重制，素材生成不可复现，等于每改一次都要重画。

## 四、skills.lock.md

```markdown
# 技能与素材锁定

| ID | 名称 | 来源 | 版本/commit | 类型 | 用途 | 结论 | 理由 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SK-01 | dialogue-tutor | github:jinshanbaihai/dialogue-tutor | 2026-09 | 教学法 | 推导行四槽位 | 采用（改写） | 密度够，但不产出视频稿，需改写 |
| SK-02 | random-signal-agent | github:PatrickStar-cmd | v0.4.11 | 素材 | AR、Welch、STFT 图 | 采用 | 固定种子，可复现 |
| SK-03 | signal-processing | clawhub:viewway | - | 内容 | 随机信号章节核对 | 参考 | 只核对公式，不作讲法 |
| SK-04 | 自建 | - | - | 素材 | 样本函数动画 | 自建 | 没有现成工具能画"多条样本 + 集平均" |

## 未采用

| 名称 | 原因 |
| --- | --- |
| Math.Skill | 解题器，不讲思路；答案可信但讲稿会变成步骤清单 |

## 待用户确认

- [ ] 是否安装 SK-02（需要 Python 3.12+）
```

**不擅自安装。** 列出来，标清依赖和风险，让用户点头。

## 五、按知识点分配

不要笼统写"用 XX 技能"，要落到知识点：

```markdown
| 知识点 | 讲法来源 | 素材来源 | 生产 |
| --- | --- | --- | --- |
| K-05-01 功率谱定义 | SK-01 四槽位 | 自建：白噪声谱图 | code-course-video |
| K-05-02 Wiener–Khinchin | SK-01 + SK-03 核对 | SK-02 Welch 对比图 | code-course-video |
| K-09-01 窄带包络 | 自建 | SK-02 STFT | code-course-video |
```

空白格要写"自建"，不能留空。留空意味着到 S4 才发现没人管。

## 六、随机信号分析的参考组合

这不是标准答案，是起点：

| 环节 | 可用的东西 | 注意 |
| --- | --- | --- |
| 讲法 | `dialogue-tutor` 的 §5 行行推导 | 它面向 TMUA/经济学，符号体系要换 |
| 内容核对 | `signal-processing` 的随机信号章节 | 只核对，不要照抄表述 |
| 波形/谱图 | `random-signal-agent` | 固定种子；记录采样率、时长、模型阶数 |
| 视频 | `code-course-video` | 必须换帧：公式 + 图，不是代码 + 输出 |

缺的那块通常是**"多条样本函数 + 集平均"的动态演示**。这个没有现成技能，要么用 Python + matplotlib 生成帧序列，要么用 Remotion 直接画。记在 `skills.lock.md` 的"自建"里。

## 七、禁止事项

- 不要把"内容型"技能当"教学法"用。知识对，不等于讲得懂。
- 不要因为技能名字里有课程名就采用。看它的输出是什么。
- 不要在一次任务里装超过 3 个新技能。装得越多，行为越不可预测。
- 不要用没有版本号的技能做可复现素材。今天能出图，明天出不来，课就废了。
- 不要跳过许可检查。要上传 GitHub 的工程，第三方素材的许可必须写清。
